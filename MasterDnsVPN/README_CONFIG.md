# Руководство по конфигурации MasterDnsVPN

В данном документе подробно описаны все основные параметры конфигурации для **Сервера** (`server_config.toml`) и **Клиента** (`client_config.toml` / или настройки внутри v2rdns).

MasterDnsVPN использует протокол DNS для инкапсуляции TCP-трафика (SOCKS5/Xray), что позволяет обходить блокировки, используя обычные DNS-резолверы.

---

## 💻 Настройки Клиента (Client Config)

### Базовые настройки подключения
*   `PROTOCOL_TYPE` — Тип локального прокси-сервера. Обычно `SOCKS5`.
*   `TCP_LISTEN_HOST` и `TCP_LISTEN_PORT` — Адрес и порт, на котором клиент будет слушать входящие локальные подключения (например, `127.0.0.1:1080`).
*   `DOMAIN` — Доменные имена (одно или несколько), которые прописаны на вашем сервере (NS-записи), на которые будут отправляться DNS-запросы.
*   `RESOLVERS` — Список публичных DNS-серверов (резолверов), через которые будет идти туннель (например, `1.1.1.1:53`, `8.8.8.8:53`). **Для кратного увеличения скорости рекомендуется указывать сразу несколько штук.**
*   `RESOLVER_BALANCING_STRATEGY` — Режим балансировки нагрузки (Multi-path) при использовании нескольких резолверов:
    *   `0` / `2` — **Round Robin** (по кругу, по умолчанию).
    *   `1` — **Random** (случайный).
    *   `3` — **Least Loss** (наименьший процент потерь).
    *   `4` — **Lowest Latency** (наименьший пинг).

### Сетевые ограничения и MTU
*   `ENABLE_EDNS0` (`true` / `false`) — Включает поддержку больших пакетов (до 4096 байт) через расширение EDNS0. **ВНИМАНИЕ:** Многие провайдеры (DPI) блокируют такие пакеты. Если интернет пропадает — ставьте `false`.
*   `MAX_DOWNLOAD_MTU` — Максимальный размер порции данных (полезной нагрузки) для скачивания за один пакет.
    *   *Примечание:* Если `ENABLE_EDNS0 = false`, этот параметр автоматически урезается клиентом до **250 байт**, чтобы итоговый размер пакета не превышал строгий стандарт DNS (512 байт) и не блокировался провайдером.
*   `MAX_UPLOAD_MTU` — Аналогично для исходящего трафика (обычно 150 байт).

### Многопоточность и агрессивность
*   `RX_TX_WORKERS` — Количество параллельных потоков запросов (Workers). Чем их больше, тем быстрее идет скачивание (так как мелкие пакеты отправляются параллельно), но растет нагрузка на процессор и сеть. Оптимально: **8, 16 или 32**.
*   `PING_AGGRESSIVE_INTERVAL_SECONDS` — Задержка перед опросом сервера, если нет активных данных (например, `0.1`). Влияет на отзывчивость сети.

### Защита и Кодирование
*   `DATA_ENCRYPTION_METHOD` — Метод шифрования (например, `1` - AES/ChaCha20).
*   `ENCRYPTION_KEY_FILE` — Путь к файлу с ключом шифрования, который должен совпадать с серверным.

## 🛠 Настройки Сервера (Server Config)

### Базовые параметры
*   `UDP_HOST` и `UDP_PORT` — Адрес и порт, на котором сервер слушает входящие DNS-запросы (Обычно `0.0.0.0:53`).
*   `PROTOCOL_TYPE` — Тип протокола.
*   `USE_EXTERNAL_SOCKS5` — Если `true`, сервер будет проксировать расшифрованный трафик на сторонний SOCKS5/Xray клиент (например, 3x-ui).
*   `FORWARD_IP` и `FORWARD_PORT` — Адрес вашего SOCKS5/Xray клиента (например, `127.0.0.1:10808`), куда сервер будет пересылать трафик.

### Ограничения клиентов (Защита от злоупотреблений)
Эти параметры выступают "потолком" — сервер не позволит клиенту запросить больше, чем указано здесь, даже если в конфиге клиента цифры выше.
*   `MAX_ALLOWED_CLIENT_RX_TX_WORKERS` — Максимальное количество параллельных потоков на одного клиента (по умолчанию 128).
*   `MAX_ALLOWED_CLIENT_DOWNLOAD_MTU` — Максимальный размер пакета, который разрешено скачивать клиенту.
*   `MAX_ALLOWED_CLIENT_ACTIVE_SESSIONS` — Лимит одновременных активных сессий с одного IP/клиента.
*   `MIN_ALLOWED_CLIENT_PING_AGGRESSIVE_INTERVAL_SECONDS` — Минимальный интервал пинга (чтобы клиент не мог "задосить" сервер частыми запросами).

### Параметры надежности (ARQ и FEC)
Туннель работает поверх ненадежного UDP. Для гарантии доставки используются два механизма:
*   **ARQ (Automatic Repeat reQuest):** Система подтверждения (ACK) получения пакетов. Если пакет утерян, сервер или клиент его переотправят.
    *   `ARQ_WINDOW_SIZE` — Сколько пакетов можно отправить до получения подтверждения.
    *   `ARQ_MAX_DATA_RETRIES` — Максимальное число попыток переотправки до разрыва соединения.
*   **FEC (Forward Error Correction):** Система упреждающей коррекции ошибок (Коды Рида-Соломона).
    *   `FEC_DATA_SHARDS` — Количество блоков данных.
    *   `FEC_PARITY_SHARDS` — Количество блоков восстановления.
    *   *Примечание:* По умолчанию включено (1 к 3). Улучшает работу на сетях с высокой потерей пакетов, но требует вычислительных ресурсов.

### Оптимизация сети
*   `ENABLE_EDNS0` — Глобальный рубильник на сервере, разрешающий отвечать большими пакетами, если клиент этого попросит.
*   `SOCKET_BUFFER_SIZE` — Размер буфера сокета операционной системы (для высоких нагрузок рекомендуется `8388608` (8МБ) и больше).

## 💡 Советы по тюнингу скорости (Best Practices)

1. **Если провайдер не блокирует DNS жестко:**
   Включите `ENABLE_EDNS0 = true` на сервере и клиенте. Скорость возрастет в десятки раз из-за больших пакетов (до 4 КБ).
2. **Если провайдер "душит" VPN (стандартный режим):**
   Отключите `ENABLE_EDNS0` (установите `false`). 
   Укажите в клиенте 4-5 разных публичных DNS-резолверов.
   Повысьте `RX_TX_WORKERS` на клиенте до `16` или `32`. Это позволит "качать через соломинку", но использовать сразу 32 таких соломинки, распределенных по разным DNS-серверам, что даст отличную скорость и максимальную устойчивость.
